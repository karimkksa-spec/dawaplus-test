# دواء بلس — نسخة الصيدلية وتجربة الجوال

## تحديث النشر السحابي — 11 أكتوبر 2026

أضيف دعم PostgreSQL وحفظ صور المنتجات داخل قاعدة البيانات. إعدادات Render واختبار النشر في [دليل النشر](docs/CLOUD-DEPLOY.md). دعم الاتصال مجهز في المصدر؛ نجاح الاختبارات المحلية لا يعني أن النشر السحابي أو تجربة الجوال قد اكتملت. تعليمات الشبكة المحلية أدناه تخص التجارب السابقة وعنوان الجهاز قد يتغير.

مشروع محلي لتوصيل منتجات دواء بلس في **عدن**، بأربع واجهات عربية متصلة بخادم واحد وقاعدة بيانات دائمة. هذه مرحلة تجريبية قابلة للتشغيل، وليست إصدارًا إنتاجيًا أو ملفات APK جاهزة.

## جديد 29 سبتمبر 2026

أُضيف تطبيق صاحب الصيدلية: إضافة وتعديل المنتجات والصور والمخزون وإخفاء المنتجات، استقبال طلبات صيدليته، القبول والرفض، وتحديد الجاهزية للكابتن. كل طلب مرتبط بصيدلية واحدة، وصلاحيات الصيدليات معزولة. أضيفت أسماء وسائل الدفع المحلية من الصور كخيارات غير مفعلة. توجد نسخة احتياطية محلية قبل ترقية قاعدة البيانات.

**للتجربة على جوالك اقرأ [دليل اختبار الهاتف](docs/PHONE-TEST.md).** افتح `http://192.168.8.13:4174/customer` وأنت على شبكة الكمبيوتر نفسها. لتشغيل نسخة الشبكة لاحقًا: `npm run demo:lan`. هذا رابط محلي، وليس استضافة عامة. نجحت 10 اختبارات آلية بعد التحديث.

## المعاينة

- العميل: http://127.0.0.1:4173/customer
- الإدارة: http://127.0.0.1:4173/admin
- الكابتن: http://127.0.0.1:4173/captain
- الصيدلية: http://127.0.0.1:4173/pharmacy
- معاينة الهاتف: http://127.0.0.1:4173/preview-mobile.html

من داخل أي واجهة اضغط تسجيل الدخول ثم زر الحساب التجريبي. الإدارة والكابتن والصيدلية لديهم زر تجربة مباشر. توجد عملية اختبار مكتملة في قاعدة البيانات المحلية؛ ليست طلبًا حقيقيًا.

## التشغيل

يتطلب Node.js 24.18 أو إصدارًا متوافقًا مع `node:sqlite`.

```powershell
npm ci --cache ../../work/npm-cache
npm run build
npm run demo
```

للتطوير شغّل الخادم أعلاه، ثم `npm run dev` في نافذة أخرى. الاختبارات: `npm test`.

الخادم الافتراضي يستمع على هذا الجهاز فقط. كل الطلبات التجريبية محفوظة في `data/dawaplus.sqlite`. لا ترفع هذه القاعدة أو ملفات البيئة الفعلية إلى مستودع عام.

## ما يعمل الآن

| العميل | الإدارة | الكابتن |
|---|---|---|
| كتالوج 51 منتجًا وبحث وتصفية | عرض الطلبات ومراجعتها | المهام المسندة له فقط |
| تفاصيل المنتج والسلة | قبول الطلب وإسناده | تأكيد استلام الطلب |
| عنوان داخل مناطق عدن | تعديل سعر المنتج والمخزون | تأكيد التسليم والتحصيل |
| حساب الرسوم والريال اليمني | تعديل رسوم المناطق | سجل التوصيلات |
| الدفع عند الاستلام | ملخص التحصيل النقدي | ملخص النقد المحصل |
| متابعة الحالة والإلغاء قبل القبول | إلغاء قبل الاستلام | فصل الصلاحيات عن الإدارة |

السلة والمفضلة حالياً ضمن الجلسة المعروضة فقط، وليستا مزامنتين مع حساب العميل. حالات الطلب تحدث باستعلام كل ست ثوان؛ ليست تتبع GPS مباشرًا. الإحصاءات إجمالية وليست أرباحًا أو تسويات محاسبية للكابتن.

الخادم يحسب الأسعار من قاعدة البيانات، يحجز المخزون في معاملة واحدة، يمنع تكرار الطلب بمعرّف المحاولة، ويعيد المخزون عند الإلغاء. يتطلب تأكيد المراجعة قبل تجهيز الطلب، وتأكيد التحصيل قبل التسليم. الجلسات مدتها ثماني ساعات، وتخزن بصمة الرمز في القاعدة، وكلمات المرور مشتقة باستخدام scrypt.

## أندرويد

اعتمدت بنية React وCapacitor لثلاثة تطبيقات منفصلة:

- `mobile/customer`: المعرّف `ye.dawaplus.customer`.
- `mobile/captain`: المعرّف `ye.dawaplus.captain`.
- `mobile/pharmacy`: المعرّف `ye.dawaplus.pharmacy`.

توجد إعدادات منفصلة وسكربت لإنشاء مشروع أندرويد وتزامن الملفات، لكن **لم تُنتج حزم APK ولم يجر اختبار جهاز أندرويد**. أداة Capacitor توقفت في البيئة الحالية عند قراءة معلومات مستخدم النظام (`uv_os_get_passwd / ENOMEM`) قبل إنشاء المشروع الأصلي. لا يوجد مشروع أندرويد مولّد يمكن اعتباره مجرّبًا حاليًا.

بعد توفير عنوان HTTPS حقيقي للخادم وأدوات Android Studio وJDK/SDK المتوافقة:

```powershell
$env:VITE_API_URL='https://YOUR-ACTUAL-API-DOMAIN'
npm run android:customer
npm run android:captain
npm run android:pharmacy
```

استبدل القيمة بعنوانك الفعلي. افتح مشروع `android` الناتج لكل تطبيق، ثم اختبر الاتصال والصلاحيات والرجوع من الخلفية وضعف الشبكة قبل إنشاء حزمة موقّعة. السكربت لا يوقع ولا ينشر التطبيقات، ولا يستخدم اتصال HTTP غير مشفر.

## ما يلزم قبل التشغيل التجاري

1. تحديد هل مصدر الطلب صيدلية واحدة أم عدة صيدليات، واعتماد المناطق والأسعار وساعات العمل.
2. اعتماد الكتالوج والمخزون وسياسة مراجعة الوصفات؛ إضافة رفع الوصفة بتخزين محمي وصلاحيات مناسبة وسجل مراجعة.
3. تسجيل العملاء والتحقق من الهاتف عبر مزود OTP، وإدارة حسابات الموظفين والكباتن واستعادة الحسابات. الحسابات الحالية للتجربة فقط.
4. الحصول على وثائق الربط وحسابات التاجر لوسائل الدفع المحددة بالصور، ثم التحقق من الدفع بخادم المزود. المحافظ الحالية غير مفعلة، ولا توجد فيزا أو بطاقات.
5. الخرائط والتتبع الفعلي والإشعارات والتنبيهات وإثبات التسليم والمرتجعات والتسويات المالية والدعم.
6. تجهيز بيئة استضافة وقاعدة بيانات إنتاجية ونسخ احتياطية ومراقبة وترحيلات واختبارات حمل ومراجعة أمنية. الخادم الحالي وقاعدة SQLite أساس للنسخة المحلية فقط.
7. اختبار تطبيقات أندرويد الثلاثة على أجهزة حقيقية، إنشاء مفاتيح توقيع يملكها صاحب المشروع، وتجهيز ملفات APK/AAB ومتطلبات النشر.

لا تدخل بيانات مرضى أو وصفات حقيقية في هذه النسخة المحلية. زر المراجعة يمثل خطوة عمل أولية، وليس نظامًا مكتملًا لإدارة الوصفات.
