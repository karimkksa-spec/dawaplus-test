# نشر نسخة الاختبار على Render وSupabase

هذه نسخة اختبار بأربع واجهات، وليست إصدار التشغيل التجاري. لا تنقل قاعدة البيانات المحلية إلى المستودع.

## الإعداد

- Node.js 24، الفرع main، Root Directory فارغ عند رفع محتويات المشروع إلى جذر المستودع.
- Build Command: `npm ci --include=dev && npm run build`
- Start Command: `npm start`
- الخطة Free، المنطقة Frankfurt، Health Check: `/api/health`.
- `NODE_ENV=production` و`HOST=0.0.0.0` و`DEMO_MODE=false`.
- `DATABASE_URL`: رابط Session pooler من Supabase، المنفذ 5432. يجب ترميز الرموز الخاصة في كلمة المرور داخل الرابط. أدخله في إعدادات Render فقط.
- يمكنك ترك كلمة المرور مؤقتة داخل الرابط، ووضع كلمة المرور الحقيقية في `DATABASE_PASSWORD`؛ عندها يرمّزها الخادم تلقائيًا ويستبدلها داخل الرابط، دون كتابتها في المصدر.
- `PILOT_ACCOUNTS`: مصفوفة JSON لحسابات اختبار خاصة بالأدوار customer/admin/captain/pharmacy، لكل حساب name وphone وpassword. كلمة المرور 16 حرفًا على الأقل. لا تضع القيمة في GitHub.

ينشئ الخادم جداول PostgreSQL داخل مخطط `dawapp` غير المعروض تلقائيًا عبر Data API، ويضيف الكتالوج المرجعي والحسابات مرة واحدة دون مسح الطلبات. يتم التحقق من شهادة TLS. إن احتاج المزود شهادة مخصصة، اضبط شهادة موثوقة؛ لا تعطل التحقق.

الصور الجديدة تحفظ داخل قاعدة البيانات (حد الصورة 1 ميجابايت)، وهو حل للنسخة التجريبية الصغيرة ويستهلك حصة قاعدة البيانات. عند التوسع انقل الصور إلى تخزين ملفات مخصص. لا تستخدم قرص Render المجاني لحفظ بيانات دائمة.

حسابات العرض ذات كلمة المرور المنشورة تعمل محليًا فقط. الخادم يرفض تشغيلها مع PostgreSQL. يمكن للعميل إنشاء حساب برقم الهاتف وكلمة المرور. لا يوجد OTP أو استعادة كلمات المرور بعد. إدارة حسابات الصيدليات والكباتن جزء من العمل اللاحق.

## اختبار ما بعد النشر

1. تحقق من `/api/health`: ok=true وstorage=postgres وdemo=false.
2. افتح `/customer` و`/pharmacy` و`/admin` و`/captain` بحساباتها الخاصة.
3. أضف منتجًا وصورة من الصيدلية، ثم اطلبه كعميل مع تحديد نقطة على الخريطة.
4. الصيدلية تؤكد ثم تجهز، الإدارة تسند الكابتن، الكابتن يستلم ثم يسلم مع تأكيد النقد.
5. جرّب مشاركة الموقع من الجوال عبر HTTPS وإيقافها؛ التتبع يعمل أثناء فتح التطبيق فقط.
6. أعد تشغيل الخدمة، ثم تحقق أن الطلب والصورة ما زالا موجودين.

الاختبارات المحلية تشمل PostgreSQL المضمن عبر PGlite؛ هذا لا يثبت اتصال Supabase الفعلي أو التزامن متعدد الاتصالات أو تجربة الجوال. يجب فحص هذه على النشر.

لم تنفذ بعد: أقرب صيدلية/كابتن تلقائيًا، عروض متزامنة للمناديب وقبول أول واحد، حساب المسافة والعمولة، محافظ فعلية، إشعارات خلفية، أو ملفات APK نهائية. الإسناد يدوي ورسوم التوصيل حسب مناطق قابلة لتعديل الإدارة.


# تحسينات دواء بلس — 15 أكتوبر 2026

- تسجيل عميل جديد بالاسم ورقم يمني وكلمة مرور محفوظة بمشتق آمن؛ لا يسمح التسجيل العام بأدوار الإدارة والصيدلية والكابتن.
- إعداد اسم الطبيب ورقم واتساب وتفعيل الاستشارات من الإدارة؛ تسجيل الطلب وتحديث حالته وإشعاراته. رابط واتساب يحتوي مرجع الاستشارة فقط ولا يرسل بيانات صحية تلقائيًا.
- توجيه يدوي للطلب أو قبول أول صيدلية تؤكد جميع الأصناف. القبول ونقل حجز المخزون داخل معاملة واحدة. المطابقة بمعرف صنف موحد والاسم والقسم والسعر؛ لا بدائل دوائية تلقائية.
- مراحل الصيدلية: استلام، تجهيز، جاهز. الكابتن: استلام من الصيدلية، في الطريق، وصل، تسليم مع تأكيد التحصيل.
- صفحة منتج مع الوصف والاستعمال والجرعة والتنبيهات والمصدر، ومنتجات القسم نفسه. الصيدلية تدخل النصوص المعتمدة، والجرعة تتطلب مصدرًا. لم نؤلف جرعات للكتالوج السابق.
- شات محفوظ بين العميل وكابتنه المعين، بعد الإسناد وحتى انتهاء الطلب. محفوظ للقراءة بعد الانتهاء؛ طلبات الإرسال المعادة لا تكرر الرسالة.
- صندوق إشعارات محفوظ مع غير المقروء، وتحديث كل 6 ثوانٍ. الشات كل 4 ثوانٍ. تنبيه متصفح اختياري أثناء فتح التطبيق.

## التحقق المحلي
نجحت الاختبارات الآلية العشرون، وتشمل SQLite وPostgreSQL المضمن PGlite وواجهات HTTP: التسجيل والصلاحيات، التنافس على قبول الطلب، المخزون والتراجع، المراحل، خصوصية الشات، الاستشارات والتكرار، إعادة تهيئة قاعدة البيانات والخرائط. نجح بناء Vite.
اختبار Chrome: إنشاء عميل، إشعار ترحيبي، إعداد الطبيب والتوجيه، طلب استشارة وتحديثه، فحص رابط واتساب دون إرسال، إكمال الطلب DP-3E7CAB7D من الصيدلية إلى التسليم، ورسائل متبادلة. فحص عرض الجوال دون تجاوز عرض الصفحة. لم يحدث توصيل أو تحصيل حقيقي.

## حدود النسخة
SMS/OTP واستعادة كلمة المرور غير مربوطين. تسجيل الحساب لا يثبت ملكية الهاتف. إشعارات الهاتف الخلفية وFCM لم تربط؛ المتاح إشعارات أثناء فتح التطبيق. لم يُبن APK أو يُختبر هاتف أندرويد فعلي. محتوى الجرعات يحتاج اعتماد الصيدلي. الرسوم حسب المنطقة والإسناد للكابتن يدوي؛ الأقرب جغرافيًا ورسوم المسافة والعمولات والمحافظ الفعلية ليست منفذة.

## النشر
الجداول الجديدة تضاف دون حذف الطلبات السابقة داخل dawapp في PostgreSQL. لا أسرار إضافية مطلوبة. إعدادات الطبيب والتوجيه من الإدارة؛ الاستشارات غير مفعلة افتراضيًا. التحقق السحابي بعد النشر مستقل عن نتائج الاختبارات المحلية.
